## Change

- `components/IconGlyph.tsx` — static twin of the runtime icon layer
  (`lib/icons.ts`): same official Material Symbols fill paths, same
  currentColor wiring and aria-hidden span, 20×20 intrinsic size (the
  stylesheets keep their per-context sizing: 18px header, 16px button).
  `hydrate()` skips spans that already contain an svg, so the runtime layer
  and the shipped markup stay in agreement. Note: the glyphs are fill-based,
  so currentColor is carried by `fill` on the svg root — `stroke` would
  render the solid paths as blocks.
- Public-page glyph spans replaced with IconGlyph: SiteHeader (menu/close,
  mail, contrast ×2, light/dark in the runtime theme dropdown),
  ReelTranscriber (arrow_forward/hourglass_top), ReelResult (check_circle),
  LandingView (folder_open), ContactView (content_copy), App feedback fab
  (mail). The app-internal views (Player/Home/Vocabulary/AddSession, 23
  spans) intentionally stay on the runtime icon layer — they are not public
  pages and are not prerendered.
- `index.html` — the home shell now ships the same `<header>` (brand, four
  nav items, mail + theme entries) and full footer (brand, tagline, About /
  Contact / Data & privacy / How it works / Settings) as the prerendered
  pages. The markup is generated by the same SSR (`SiteHeader`/`Brand`/
  `Link`) and pinned byte-identical by `tests/home-chrome.test.cjs`. The
  four transcript-guide links are unchanged verbatim and now sit after the
  five page links, matching the runtime footer layout.
- `lib/home-faq.ts` — first answer now reads: "A public Instagram Reel or
  feed-video link: instagram.com/reel/…/, instagram.com/reels/…/, or a
  instagram.com/p/…/ post that actually contains video. Private accounts,
  Stories, profile links and photo-only posts cannot be processed." The
  other five answers are pinned verbatim in tests. Single source flows into
  the static FAQ section, the React section and the FAQPage JSON-LD.
